# Geocaching @ Northeastern

A web app for logging and finding geocaches around Northeastern
University, with room to scale to the city of Boston.

## Project structure

```
f26-group-12/
├── .gitignore          Single source of truth for ignore rules
├── README.md
├── supabase/           Backend: database + server-side functions
│   └── schema.sql      Reference dump of the current schema
└── frontend/           Vite + React app
    ├── package.json    Dependencies live here
    ├── .env.example    Committed template -- copy, don't edit
    └── src/
```

Supabase is the backend. There is no Node server, so there is no
`backend/` package: database schema lives in `supabase/`, and
server-side code belongs in Supabase Edge Functions
(`supabase/functions/`), which run on Deno.

`node_modules/` is generated by `npm install` and belongs next to
the `package.json` that created it. It is never committed.

## Getting started

```bash
git clone git@github.com:Oasis-NEU/f26-group-12.git
cd f26-group-12/frontend
npm install
cp .env.example .env.local   # then fill in your own values
npm run dev
```

`.env.local` is gitignored. It holds your personal credentials and
must never be committed. If you need values, ask in the team chat --
never paste keys into a file git can see, and never into a commit.

### Which keys go where

Vite inlines every `VITE_`-prefixed variable into the JavaScript
bundle shipped to the browser, where anyone can read it in devtools.
The prefix is an opt-in to publication, not a secret store.

| Variable | Location | Public? |
|---|---|---|
| `VITE_SUPABASE_URL` | `frontend/.env.local` | Yes |
| `VITE_SUPABASE_ANON_KEY` | `frontend/.env.local` | Yes — safe only with RLS enabled |
| `VITE_GOOGLE_MAPS_API_KEY` | `frontend/.env.local` | Yes — must be referrer-restricted |
| `ANTHROPIC_API_KEY` | `supabase secrets set` | **Never** — server-side only |
| `SUPABASE_SERVICE_ROLE_KEY` | `supabase secrets set` | **Never** — server-side only |

The anon key being public is why Row Level Security is mandatory:
that key reaches every visitor's browser, so a table without
policies is readable and writable by the whole internet.
## Working with Claude Code

The repo ships with Claude Code skills and commands in `.claude/`,
so they load automatically. No plugin installs needed.

| Framework | What it's for | Try |
|---|---|---|
| `husky-geocaching` | Our project conventions | Loads on its own |
| Superpowers | Brainstorming, planning, debugging | "Use the brainstorming skill" |
| OpenSpec | Writing a reviewable plan for each feature | `/opsx:explore`, `/opsx:propose` |
| GSD Core | Phase-based planning for bigger chunks of work | `/gsd-help` |

All three plan-then-build frameworks overlap. Pick one per task
rather than mixing them mid-feature.

### Setup

1. `git pull`, then start a **new** Claude Code chat. Skills load
   at session start.
2. **OpenSpec** needs its CLI installed once:
```bash
   npm install -g @fission-ai/openspec@1.14.1
```
   On a Mac, if that fails with `EACCES: permission denied`, do
   **not** use `sudo`. Give npm a folder you own instead:
```bash
   mkdir -p ~/.npm-global
   npm config set prefix ~/.npm-global
   echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.zshrc
   source ~/.zshrc
```
   then rerun the install.
3. **GSD hooks (optional).** GSD's automatic guards (e.g. blocking
   Claude from reading `.env` files) live in your personal
   `.claude/settings.local.json`, which is gitignored. To get them,
   run from the repo root:
```bash
   npx @opengsd/gsd-core@1.16.0 --claude --local --profile=core
```

### Rules

- **Never run `claude --dangerously-skip-permissions`.** Some tools
  recommend it. It lets Claude run anything without asking.
- **Review changes to `.claude/` like code.** Skills are instructions
  Claude follows and hooks run automatically, so a bad edit there
  affects everyone.
- **Pin versions when installing tools.** Pick a release at least two
  weeks old (`npm view <package> time`), never `@latest`.

## Conventions

**Routing.** Import from `react-router`, never `react-router-dom`.
From v7 onward `react-router` exports the DOM bindings directly;
installing both pulls in two copies with separate React contexts and
causes errors like `useNavigate() may be used only in the context of
a <Router>`.

**Branches.** Use `type/short-description`:
`feature/cache-map`, `fix/add-gitignore`, `chore/update-deps`.

**Commits.** One logical change per commit. Write what the commit
*does*, not what you intended -- a message that disagrees with its
diff is worse than no message, and has already cost this project a
`.gitignore`.

**Never commit:** `node_modules/`, `dist/`, any `.env` file, or
anything containing a credential. If you think you've committed a
secret, say so immediately -- rotating a key takes minutes, and the
alternative is a key that stays exposed in history forever.
