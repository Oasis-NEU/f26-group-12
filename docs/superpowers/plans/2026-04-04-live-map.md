# Live Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the placeholder home map with the responsive Figma map, powered by read-only Supabase cache/find queries and Google Maps when configured.

**Architecture:** Keep map data selection and filtering in a small pure/helper module, then have `MapPage` own loading, auth state, realtime refresh, responsive controls, and marker selection. Use the existing map provider dependency and shared Supabase client; do not modify database permissions or secrets.

**Tech Stack:** Vite, React, Tailwind CSS, Supabase JS, `@vis.gl/react-google-maps`, Node's built-in test runner.

**Spec:** `docs/superpowers/specs/2026-04-04-live-map-design.md`

## Global Constraints

- Keep the requested stack: Vite + Tailwind CSS + React + Supabase.
- Do not inspect or edit `.env.local` or credential values.
- Keep all Supabase operations read-only and exclude `secret_code` from selections.
- Do not change database schema, RLS policies, grants, or Realtime publication settings.
- Use `react-router`, not `react-router-dom`.

## Review Focus

- A returned cache must never contain a requested `secret_code` column — test the selected-column contract.
- Search and filters must compose correctly and avoid exposing found caches in “To find” — test the filter helper with found/unfound cache records.
- Logged-out state must not query or subscribe to any user's finds — test helper inputs/conditions where practical and inspect the auth-gated code.
- Empty results and missing/error configuration must remain understandable — verify the explicit empty/error UI states.
- Never subscribe to cache events because full-row payloads could include `secret_code`; subscribe only to the current user's filtered find channel and re-fetch on change.

- Create: `frontend/tests/mapData.test.js`
- Modify: `frontend/package.json` (add a built-in `node --test` script)

**Interfaces:**
- `loadActiveCaches(supabase)` returns active cache records with only `id`, `title`, `latitude`, `longitude`, `location_name`, and `difficulty`.
- `loadUserFinds(supabase, userId)` returns the signed-in user's `cache_id` values only.
- `filterCaches(caches, query, filter, foundIds)` returns records matching the query and `all` / `to-find` / `my-finds` filter.
